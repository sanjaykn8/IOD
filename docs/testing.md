What the tests establish:

* **Segmentation** (`python-service/tests/test_patch_segmentation.py`): every pixel in exactly one region, dense ids, 4-connectivity of every region, determinism, count bounds, count varies with size and content, regions are not rectangles, minimum-size merge, coarser refinement levels and their bound, setting validation.
* **Manifest / bootstrap / frame structure** (`test_patch_manifest.py`, `rust-core/src/transport/manifest.rs`, `frame.rs`): the documented test vector byte for byte in both languages, round trip, 27 + 33 malformed-field cases, canonical RLE, CRC and semantic preamble checks, length overflow, MAC over header ‖ manifest ‖ wire, every single-byte flip rejected, wrong key/direction/channel, v1 frames rejected.
* **Algorithms on masks** (`test_patch_algorithms.py`): all ten on an irregular mask, gray and RGB, through PNG, with no change outside the mask; exact measured capacity and overflow rejection; two adjacent patches do not interfere; block methods touch only complete blocks; unsupported geometry is reported (no LSB substitution); STC changes concentrate in texture; edge-adaptive carrier set is independent of neighbouring patches.
* **Knowledge base / retrieval** (`test_patch_kb.py`): schema validation (14 broken variants), BM25 recomputed independently from the documented formula, filters before ranking, tie break, nothing eligible → no selection, determinism, no socket use, no LLM modules loaded.
* **Planner / codec** (`test_patch_planner_codec.py`): plan → embed → PNG → extract exact on five covers × three sizes, sequential contiguous chunks covering the payload once, reserved bootstrap rows untouched by patches, bounded refinement then rejection, no silent algorithm fallback, receiver does not call the segmenter, tampered carrier fails closed, tampered payload yields a different frame.
* **Cover generator** (`test_generator_families.py`, `test_generator_quality.py`, `test_generator_select.py`, Rust `transport/generator.rs`): every family produces valid RGB and grey images of the requested size, deterministic for a test seed and different for different seeds; no clipping, no exact tiling, no dependence on payload; production seeds come from `os.urandom` and no raw seed appears in any output; the quality gates accept generated covers and reject flat, saturated, white-noise, striped, tiled, posterised, ramp and legacy black/white images, each with its reason; score weights/thresholds are configurable; profile defaults, hard ceilings, tighten-only resolution and rejection of seed / file / artifact / source / algorithm fields in **both** languages (mirrored cases); environment overrides bounded; memory pre-flight; candidate selection picks the best-scoring feasible candidate, respects `max_candidates` and the budget (checked before each step, late plan flagged), rejects on quality, capacity, embedding rate or budget with a candidate table and never tries another source; payload-driven resize follows the ladder inside the ceiling.
* **Service / HTTP** (`test_patch_service_api.py`): a fresh cover per plan; generation settings applied and validated; old cover sources, seeds and images rejected without storing anything; a re-plan reuses the stored cover and does not call the generator; only service-generated covers (with a matching sidecar) can be re-planned or embedded into; encode never generates; removed routes (`/stego/camera/probe`, `/stego/cover/upload`, `/stego/capture`) return 404; saved PNG re-read from disk, inspection artifacts, validation of every request field, failed encode leaves no file, removed routes return 404, forbidden fields rejected.
* **Rust pipeline** (`tests/stego_pipeline.rs`): both directions; every transmission generates exactly one cover (four identical messages → four covers) and the receiver triggers none; an induced embed failure re-plans with `replan_cover_id` on the same cover (generation count unchanged, both encodes name that cover); invalid generation settings fail before any backend call and without consuming a sequence number; generation failures are terminal with exactly one plan call; benchmark = one fresh cover per run, labelled as a profile-constrained host measurement; planning receives lengths and the validated settings only (request keys asserted); receiver works from the file alone; 20 tamper cases on the stored image (algorithm id, parameter, image size, patch map, chunk lengths, swapped algorithms, swapped regions, unused→used patch, offset, length, unknown id, patch count, versions, map label, frame length/version/magic, ciphertext, tag, truncation, image header) → `FRAME_AUTH_FAILED` or a strict structural code, never a delivery; Rust rejects bad manifests even when the image service passes them on; MAC-valid frames with invalid manifests are rejected; replay/out-of-order; capacity and size rejections recorded; bounded re-plan (and no algorithm fallback); manifest validation before authentication; no secrets in events, reports or CSV.
* **Real end to end** (`tests/stego_e2e_python.rs`): both directions with real PNGs, an independent reader (`tests/helpers/tamper_png.py`, stdlib + numpy + Pillow, no project code) agrees with the manifest; covers are generated by the service with OS randomness (family, fingerprint, quality score, candidate table, timings, budget; no raw seed in responses or sidecars); generated covers yield irregular patches, ≥ 2 algorithms and ≥ 2 families across transmissions; planning one stored cover twice reproduces the same manifest; **an induced re-plan against the real service** keeps the same cover id and SHA-256 with one cover file on disk; 32 pixel-level tamper cases incl. manifest rewrites **with a repaired CRC**; payloads above the embedding-rate limit are rejected with structured details and nothing written, the same payload is delivered when payload-driven resize is allowed, and the ceiling still rejects a 150 kB message; camera, upload and capture routes are 404 and every old cover request shape is rejected; a PNG placed in the artifact directory cannot be used as a cover; knowledge base served; old endpoints 404.
* **Evaluation tools** (`test_eval_tools.py`): AUC against brute force incl. ties, confusion counts, the from-scratch logistic regression on separable and noise data, chance-level result for identical classes with the paired split, feature determinism, real extractable stego builders, benchmark statistics and host metadata.
* **Learning workbench** (`test_learn_workbench.py`, `tests/learn_workbench.rs`): patch-level experiments, metrics recomputed from returned images, survey, isolation from the operational store, production knowledge base file unchanged.
